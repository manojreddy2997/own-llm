Artificial intelligence is a field of computer science focused on building systems that can perform tasks that normally require human intelligence. Machine learning is a major area of artificial intelligence. A machine learning model learns patterns from data and uses those patterns to make predictions.

Supervised learning uses labeled training data. Each training example contains an input and an expected output. The model compares its prediction with the expected output and adjusts its parameters to reduce the error. Classification predicts categories, while regression predicts numerical values.

Unsupervised learning works with data that does not have labeled outputs. Clustering groups similar examples together. Dimensionality reduction transforms data into a smaller representation while attempting to preserve important information.

A language model predicts tokens. During training, a next-token language model receives a sequence of tokens and learns to predict the next token. The model produces logits for every possible token in its vocabulary. A probability distribution is obtained by applying softmax to the logits.

Machine learning is a branch of artificial intelligence that enables computers to learn patterns from data. Instead of writing every rule manually, engineers provide examples and allow an algorithm to learn a function that maps inputs to outputs.

A machine learning dataset normally contains examples and features. A feature represents an input variable used by a model. A target represents the value that the model attempts to predict. In supervised learning, training examples contain both features and targets.

Self-attention allows a token to interact with other tokens in the same sequence. The attention mechanism uses queries, keys, and values. Queries represent what a token is looking for, keys represent information available for matching, and values contain information that can be aggregated.

Attention scores are computed by comparing queries with keys. The scores are scaled by the square root of the key dimension. A softmax operation converts the scores into weights. The weighted values are then combined to produce the attention output.

Multi-head attention uses several attention heads. Each head can learn different relationships between tokens. The outputs from the heads are combined and projected back into the model embedding dimension.

DATA ENGINEERING

Data engineering is the practice of collecting, transforming, 
storing, and delivering data so that it can be used for 
analytics, machine learning, reporting, and applications. A data 
engineer designs systems that move data from source systems into 
reliable destinations.

A data pipeline is a sequence of operations that moves data from 
one location to another. A typical pipeline extracts data from a 
source, transforms the data, validates the results, and loads 
the processed data into a destination.

ETL stands for Extract, Transform, and Load. Extract means 
reading data from a source. Transform means cleaning or changing 
the data. Load means writing the transformed data into a 
destination such as a database or data warehouse.

ELT stands for Extract, Load, and Transform. In an ELT 
architecture, raw data is first loaded into a storage or 
warehouse system and transformations are performed after 
loading.

Batch processing handles data in groups at scheduled intervals. 
Streaming processing handles data continuously as events arrive. 
Batch processing is useful for daily reports, while streaming 
can be useful for monitoring, fraud detection, and real-time 
applications.

A data warehouse is a system designed for analytical queries. 
Data warehouses commonly store structured data and support 
aggregation, filtering, joins, and reporting.

A data lake stores large amounts of raw or processed data in its 
original or semi-structured form. A lake can contain structured 
data, JSON documents, logs, images, and other files.

Data quality is important in every pipeline. Common data quality 
problems include missing values, duplicate records, invalid 
values, inconsistent formats, and incorrect relationships.

A reliable pipeline should validate input data before processing 
it. Validation can check required columns, data types, ranges, 
uniqueness, null values, and referential relationships.

Apache Spark is a distributed data processing framework. Spark 
can process large datasets by dividing computation across 
multiple machines. Spark supports batch processing, SQL, 
streaming, and machine learning workloads.

SQL is used to query relational databases. A SELECT statement 
retrieves data. A WHERE clause filters rows. GROUP BY creates 
groups for aggregation. ORDER BY sorts results. JOIN combines 
related tables.

A primary key uniquely identifies a row in a table. A foreign 
key creates a relationship between tables by referring to a key 
in another table.

Indexes can improve query performance by providing an efficient 
structure for finding records. Indexes can increase storage 
usage and can make inserts and updates more expensive.

A database transaction is a logical unit of work. Transactions 
commonly follow the ACID properties: atomicity, consistency, 
isolation, and durability.

Cloud data engineering uses services for storage, compute, 
databases, messaging, orchestration, and monitoring. A cloud 
data pipeline may use object storage for raw files, distributed 
compute for transformations, a warehouse for analytics, and an 
orchestration system for scheduling.

MACHINE LEARNING

Machine learning is a field of artificial intelligence in which 
models learn patterns from data.

Supervised learning uses labeled examples. The model receives 
input data and a target value and learns a mapping between them.

Classification predicts a category. Examples include spam 
detection and sentiment classification.

Regression predicts a numerical value. Examples include price 
prediction and demand forecasting.

Unsupervised learning works with data without explicit target 
labels. Clustering is an example of unsupervised learning.

Training is the process of adjusting model parameters to reduce 
an objective or loss function.

Inference is the process of using a trained model to produce 
predictions for new input.

A loss function measures how different a model prediction is 
from the expected target. During training, an optimizer changes 
model parameters to reduce the loss.

Gradient descent is an optimization algorithm. It calculates 
gradients of the loss with respect to model parameters and 
updates the parameters in the direction that reduces the loss.

A learning rate controls the size of parameter updates. A 
learning rate that is too large can make training unstable. A 
learning rate that is too small can make training very slow.

Overfitting occurs when a model learns the training data too 
closely and performs poorly on unseen data. Underfitting occurs 
when a model is too simple to learn the important patterns in 
the data.

A validation dataset is used to evaluate generalization during 
development. A test dataset is normally reserved for final 
evaluation.

Regularization methods can reduce overfitting. Dropout randomly 
removes some activations during training. Weight decay penalizes 
large parameter values.

Accuracy measures the fraction of correct predictions. Precision 
measures how many predicted positive examples are actually 
positive. Recall measures how many actual positive examples are 
correctly identified. The F1 score combines precision and 
recall.


NEURAL NETWORKS

A neural network contains layers of learnable parameters. Each 
layer transforms its input into a new representation.

An embedding converts discrete identifiers such as tokens into 
continuous vectors.

A hidden layer contains intermediate representations learned by 
the network.

An activation function introduces non-linearity. ReLU and GELU 
are common activation functions.

Backpropagation calculates gradients by applying the chain rule 
through the network.

An optimizer uses gradients to update parameters.

Batch size determines how many training examples are processed 
before an optimizer update.

An epoch represents one complete pass through the training 
dataset.


TOKENIZATION

Tokenization converts text into smaller units called tokens.

A token can represent a complete word, part of a word, 
punctuation, whitespace, or another text unit.

A vocabulary maps tokens to integer token IDs.

A language model does not directly process words as 
human-readable strings. It processes numerical token IDs.

Subword tokenization allows a model to represent common words as 
complete tokens while representing uncommon words as multiple 
smaller tokens.

Byte Pair Encoding, commonly called BPE, begins with small units 
and repeatedly merges frequently occurring pairs.

BPE helps control vocabulary size while allowing the model to 
represent words that were not explicitly stored as complete 
vocabulary entries.

A tokenizer has an encoder that converts text into token IDs and 
a decoder that converts token IDs back into text.

Special tokens can represent padding, unknown tokens, beginning 
of sequence, and end of sequence.


LANGUAGE MODELS

A language model estimates probabilities over sequences of 
tokens.

Autoregressive language models predict the next token based on 
previous tokens.

For example, given the sequence "machine learning uses", a 
language model predicts a probability distribution for the next 
token.

Next-token prediction is the core training objective of many 
generative language models.

During training, the model receives a sequence of tokens and 
attempts to predict the next token at every position.

Cross-entropy loss is commonly used for next-token prediction.

A lower language-model loss generally indicates that the model 
assigns higher probability to the correct next tokens.

During generation, the model produces one token at a time. The 
generated token is appended to the context and becomes input for 
the next prediction.

Greedy decoding selects the token with the highest probability.

Temperature changes the sharpness of the probability 
distribution. Lower temperature makes generation more 
deterministic. Higher temperature produces more randomness.

Top-k sampling restricts sampling to the k most probable tokens.

Top-p sampling selects a group of tokens whose cumulative 
probability reaches a chosen threshold.

Repetition can occur when a language model repeatedly selects 
tokens or phrases that become highly probable in the current 
context.


TRANSFORMERS

The Transformer is a neural network architecture based on 
attention mechanisms.

Transformers process token representations using self-attention 
and feed-forward networks.

Self-attention allows each token to interact with other tokens 
in the sequence.

Attention uses three representations called Query, Key, and 
Value.

A query represents what the current token is looking for. A key 
represents information that can be matched against a query. A 
value contains the information that is passed forward after 
attention is calculated.

Attention scores are calculated using the similarity between 
queries and keys.

The scaled dot-product attention equation is:

Attention(Q,K,V) = softmax(QK^T / sqrt(d_k))V

The scaling factor prevents attention scores from becoming 
excessively large when the dimensionality of the key vectors 
increases.

A causal language model must not allow a token to attend to 
future tokens during training. A causal mask prevents attention 
to future positions.

Multi-head attention uses several attention heads. Each head can 
learn different relationships between tokens.

After attention, Transformer blocks commonly use a feed-forward 
network.

Layer normalization helps stabilize training.

Residual connections allow information to flow around a neural 
network layer and help deep networks train more effectively.

Positional information tells the model where tokens occur in a 
sequence. Transformers require positional information because 
self-attention itself does not inherently provide token order.

A Transformer block commonly contains normalization, 
self-attention, residual connections, a feed-forward network, 
and another residual connection.


GPT

GPT stands for Generative Pre-trained Transformer.

A GPT-style model is an autoregressive Transformer language 
model.

A GPT model begins with token embeddings and positional 
information.

The embeddings are passed through multiple Transformer blocks.

The final hidden representation is projected into 
vocabulary-sized logits.

Logits are unnormalized scores for possible next tokens.

Softmax converts logits into probabilities.

The model selects or samples a token from the probability 
distribution and continues generation.

Training a GPT model requires many examples of text. More 
diverse and higher-quality training data generally allows the 
model to learn more useful language patterns.

A small GPT model can be useful for learning how tokenization, 
embeddings, attention, Transformer blocks, loss functions, 
optimization, and generation work.


RAG

Retrieval-Augmented Generation combines information retrieval 
with language generation.

A RAG system retrieves relevant information from an external 
knowledge source before generating an answer.

A typical RAG pipeline contains document loading, text cleaning, 
chunking, embedding, vector storage, retrieval, and generation.

Chunking divides large documents into smaller pieces.

Good chunks should contain enough information to answer 
questions while remaining focused.

Embeddings represent text as vectors in a numerical space.

Semantically similar text should have nearby vector 
representations.

A vector database stores embeddings and supports similarity 
search.

When a user asks a question, the question can be converted into 
an embedding.

The system searches the vector database for relevant chunks.

The retrieved chunks are added to the model context.

The language model uses the retrieved context to generate a 
grounded answer.

RAG can reduce hallucination by giving a language model access 
to external information.

RAG quality depends on both retrieval quality and generation 
quality.

If the correct information is not retrieved, the language model 
may not be able to produce a correct grounded answer.

Retrieval can use cosine similarity, dot product similarity, or 
other distance measures.

A RAG system can use reranking to improve the ordering of 
retrieved documents.

Query rewriting changes the user's original query into a form 
that may produce better retrieval results.

Multi-hop retrieval performs multiple retrieval steps when 
answering a question requires information from several sources.


AI AGENTS

An AI agent is a system that uses a language model to reason 
about a task and interact with tools or external systems.

An agent can receive a goal, plan actions, call tools, observe 
results, and decide what to do next.

Tools allow an agent to perform operations that the language 
model cannot perform by itself.

Examples of tools include search, databases, calculators, APIs, 
file systems, and application services.

A tool call contains the information required to execute an 
operation.

The tool returns an observation or result to the agent.

The agent uses the observation to decide the next action.

Agent loops should have limits on the number of steps to prevent 
infinite execution.

Production agents should also consider latency, cost, 
reliability, permissions, security, and error handling.

Agent memory can store useful information across multiple 
interactions.

Short-term memory contains the current conversation context. 
Long-term memory can store information for future tasks.

A planner can decompose a complex request into smaller actions.

A router can choose which tool, data source, or specialized 
agent should handle a request.

A validator can check whether a tool result or generated answer 
satisfies required constraints.

MCP, or Model Context Protocol, provides a standardized way for 
AI applications to connect models with tools and external data 
sources.

An MCP server can expose tools, resources, or prompts to an MCP 
client.

MCP can make integrations reusable across different AI 
applications.


MODEL EVALUATION

Language model evaluation should measure both numerical metrics 
and actual generated behavior.

Validation loss measures how well the model predicts tokens in 
held-out data.

Perplexity is related to language-model loss and can be 
interpreted as a measure of uncertainty over the next token.

A good evaluation set should be separated from the training 
data.

Generation tests should include different prompts and should 
check coherence, relevance, repetition, and factual consistency.

Automated metrics are useful, but human inspection of generated 
samples is also important.

A model should be evaluated on prompts that represent its 
intended use case.

Overfitting can be detected when training loss continues 
decreasing while validation loss begins increasing.

Early stopping can stop training when validation performance 
stops improving.

A checkpoint stores model parameters so that the best version 
can be restored later.


PRODUCTION AI SYSTEMS

A production AI system requires more than a trained model.

Important components include data pipelines, model serving, 
monitoring, logging, evaluation, security, access control, and 
error handling.

Observability allows developers to understand system behavior.

Logs can record requests, tool calls, errors, latency, and model 
outputs while respecting privacy requirements.

Model versioning makes it possible to reproduce and compare 
experiments.

Data versioning tracks which dataset was used to train a model.

A reproducible experiment records model configuration, tokenizer 
version, dataset version, random seeds, training parameters, and 
evaluation results.

Security is important when models can access tools or private 
information.

An AI system should follow the principle of least privilege and 
only allow the operations required for a task.

Prompt injection is an attack in which untrusted text attempts 
to influence the behavior of an AI system.

Applications that retrieve external content should treat 
retrieved text as untrusted data.

Tool permissions should be explicitly controlled.

A reliable AI system should have fallbacks when retrieval, 
tools, or model generation fail.

DEEP LEARNING

Deep learning is a branch of machine learning that uses neural 
networks with multiple layers to learn representations from 
data.

A deep neural network can contain an input layer, multiple 
hidden layers, and an output layer. Each layer transforms the 
representation produced by the previous layer.

Neural network parameters are usually initialized with small 
values. During training, the parameters are updated using 
gradients calculated through backpropagation.

A neuron computes a weighted combination of its inputs and 
applies an activation function.

The weights determine how strongly different input features 
influence the output.

Bias parameters allow a layer to shift its activation function.

A linear layer applies a matrix transformation followed by an 
optional bias.

The output of one neural network layer becomes the input of the 
next layer.

GELU is an activation function commonly used in Transformer 
architectures. GELU smoothly weights inputs rather than simply 
setting negative values to zero.

ReLU is a simple activation function defined as the maximum of 
zero and the input.

Normalization can make optimization more stable by controlling 
the distribution of intermediate representations.

Layer normalization normalizes features within each individual 
example and is commonly used in Transformer models.

Batch normalization normalizes activations using statistics 
calculated across a batch. It is common in convolutional neural 
networks.

Residual connections add the input of a layer to its output. 
They help information and gradients flow through deep networks.

A neural network can learn hierarchical representations. Earlier 
layers may learn simpler patterns while later layers can combine 
those patterns into more complex representations.


TRAINING NEURAL NETWORKS

A training loop repeatedly loads batches, performs a forward 
pass, calculates loss, computes gradients, updates parameters, 
and clears gradients.

The forward pass calculates the model prediction from the input.

The loss function compares predictions with target values.

Backward propagation calculates the gradient of the loss with 
respect to model parameters.

The optimizer updates parameters using the calculated gradients.

Gradients should normally be cleared before calculating the next 
update.

An optimizer such as AdamW maintains information about previous 
gradients to make parameter updates more effective.

Adam combines ideas related to momentum and adaptive learning 
rates.

AdamW separates weight decay from the gradient update.

A learning-rate scheduler changes the learning rate during 
training.

Cosine annealing gradually decreases the learning rate following 
a cosine-shaped schedule.

Early stopping terminates training when validation performance 
stops improving.

A checkpoint stores the parameters of a model at a particular 
point during training.

Saving the best validation checkpoint is usually better than 
simply saving the final epoch because later epochs may overfit.

A random seed can make experiments more reproducible.

Reproducibility is important when comparing different model 
configurations.

Training metrics should be recorded so experiments can be 
compared later.


LLM TRAINING

Large language models are neural networks trained on very large 
collections of text.

Pretraining teaches a language model general patterns of 
language using a self-supervised objective.

Self-supervised learning creates training targets from the input 
data itself.

In next-token prediction, the target for each position is the 
token immediately following the input token.

For example, the sequence "Data engineering is" can be used to 
predict the next token "powerful".

During training, the model predicts every next token in a 
sequence simultaneously using a causal attention mask.

Teacher forcing means that the model receives the correct 
previous tokens while learning to predict the next token.

During inference, the model instead receives its own previously 
generated tokens.

This difference between training and inference is called 
exposure bias.

A language model's parameters contain learned numerical 
representations of patterns from its training data.

Model size is often described by the number of parameters.

A parameter is a learned numerical value that is adjusted during 
training.

Increasing the number of parameters can increase model capacity, 
but larger models also require more computation and data.

Training data quality is extremely important. Duplicated, noisy, 
incorrect, or poorly formatted data can reduce model quality.

Data preprocessing may include removing unwanted markup, 
normalizing text, filtering corrupted documents, and removing 
duplicates.

Data contamination occurs when evaluation information appears in 
training data and can make evaluation results misleading.


CONTEXT WINDOWS

A context window is the maximum number of tokens a model can 
process as context in a single operation.

If a model has a context length of 2048 tokens, it cannot 
directly process a sequence longer than 2048 tokens without a 
strategy for handling longer text.

Longer context windows allow models to consider more information 
at once but increase computational requirements.

During autoregressive generation, the model repeatedly adds new 
tokens to the context.

When the context becomes longer than the model's maximum length, 
older tokens may need to be removed or compressed.

Context management is important in long conversations and RAG 
systems.

A RAG application can retrieve only the most relevant chunks to 
avoid filling the context window with unnecessary information.


ATTENTION

Attention allows a neural network to dynamically determine which 
parts of an input are important.

Self-attention means that queries, keys, and values are 
generated from the same sequence.

Cross-attention uses queries from one sequence and keys and 
values from another sequence.

Attention weights represent how strongly one token attends to 
another token.

The attention matrix contains relationships between every pair 
of positions in a sequence.

For a sequence of length N, standard self-attention creates an N 
by N attention relationship matrix.

This makes standard attention computationally expensive for very 
long sequences.

Causal attention restricts each position so that it can only 
attend to itself and earlier positions.

The causal mask is usually represented as a lower triangular 
matrix.

The diagonal of a causal attention mask allows each token to 
attend to itself.

Positions above the diagonal are masked because they represent 
future tokens.

Attention scores are converted into probabilities using softmax.

The probabilities across the attended positions sum to one.

Multi-head attention allows different heads to learn different 
types of relationships.

One attention head might focus on local relationships while 
another may learn longer-range relationships.

The outputs of the attention heads are concatenated and 
projected back into the model embedding dimension.


TRANSFORMER ARCHITECTURE

A Transformer is built from repeated Transformer blocks.

A typical Transformer block contains self-attention followed by 
a feed-forward network.

Residual connections surround the major sublayers.

Layer normalization is applied to stabilize the representations.

The Transformer architecture avoids recurrence and can process 
all positions in a sequence in parallel during training.

Parallel processing makes Transformers highly suitable for 
large-scale training.

The Transformer architecture was introduced as an alternative to 
recurrent architectures for sequence modeling.

Modern large language models are largely based on Transformer 
architectures or architectures derived from them.

GPT uses decoder-style causal Transformer blocks.

An encoder Transformer can attend bidirectionally and is useful 
for tasks such as representation learning.

Decoder-style causal models are designed for autoregressive 
generation.

The output vocabulary projection converts the final hidden state 
into one score for every vocabulary token.

The number of output logits equals the vocabulary size.


POSITIONAL INFORMATION

Self-attention alone does not inherently know the order of 
tokens.

Positional information provides information about token 
positions.

Learned positional embeddings assign a trainable vector to each 
position.

The position embedding is added to the token embedding before 
the Transformer blocks.

Sinusoidal positional encoding uses deterministic mathematical 
functions to represent positions.

Rotary Position Embeddings, commonly called RoPE, encode 
positional information by rotating query and key 
representations.

RoPE is widely used in modern language models.

Position representations allow a model to distinguish sequences 
such as "dog bites man" and "man bites dog".

The maximum context length of a model can be limited by the 
positional representation used by the architecture.


TOKEN EMBEDDINGS

Token embeddings convert token IDs into dense numerical vectors.

Each vocabulary token has a corresponding embedding vector.

If the embedding dimension is 512, each token is represented by 
a vector containing 512 numerical values.

Tokens with similar learned usage patterns may develop similar 
embedding representations.

Embeddings are learned during language-model training.

The embedding matrix has dimensions vocabulary size by embedding 
dimension.

For example, a vocabulary of 10,000 tokens and an embedding 
dimension of 512 requires an embedding matrix containing 
5,120,000 parameters.

The same embedding representation can be reused at different 
positions in a sequence.


LOGITS AND PROBABILITIES

The final layer of a language model produces logits.

A logit is an unnormalized score for a possible next token.

A vocabulary with 10,000 tokens produces 10,000 logits for each 
predicted position.

Softmax converts logits into probabilities.

The highest probability token is the most likely token according 
to the model.

Greedy decoding selects the highest probability token every 
time.

Sampling introduces controlled randomness.

Temperature modifies logits before softmax.

When temperature is below one, high-probability tokens become 
more dominant.

When temperature is above one, the probability distribution 
becomes flatter.

Top-k sampling keeps only the k highest-scoring tokens before 
sampling.

Top-p sampling keeps the smallest set of tokens whose cumulative 
probability exceeds a chosen probability threshold.

Sampling parameters strongly affect the style and diversity of 
generated text.


LANGUAGE MODEL LOSS

Cross-entropy loss measures the difference between the target 
token distribution and the predicted distribution.

For a single target token, the loss becomes larger when the 
model assigns a low probability to the correct token.

The training objective is to minimize the average cross-entropy 
loss across training examples.

Training loss measures performance on examples used to optimize 
the model.

Validation loss measures performance on examples that were not 
used directly for parameter updates.

A model can have low training loss and high validation loss when 
it overfits.

The gap between training and validation loss provides 
information about generalization.

Perplexity can be calculated from cross-entropy loss.

Perplexity approximately represents how uncertain the model is 
when predicting the next token.

Lower perplexity generally indicates better predictive 
performance on the evaluation dataset.


RAG ARCHITECTURE

A production RAG pipeline usually begins by ingesting documents.

Documents can come from PDFs, web pages, databases, cloud 
storage, internal knowledge bases, or application APIs.

Documents are cleaned before being divided into chunks.

Chunking strategies include fixed-size chunks, sentence-based 
chunks, paragraph-based chunks, and semantic chunks.

Chunk overlap preserves information across chunk boundaries.

Each chunk is converted into an embedding vector.

The vectors are stored in a vector index or vector database.

The original chunk text and metadata are usually stored 
alongside the vector.

Metadata can contain document name, page number, section, 
timestamp, source, and access information.

At query time, the user's question is embedded using the same or 
compatible embedding model.

Similarity search returns candidate chunks.

The system may retrieve more candidates than it ultimately sends 
to the language model.

A reranker can score the candidates more precisely.

The highest-quality chunks are inserted into the generation 
context.

The language model generates an answer using the retrieved 
information.

A citation system can show which documents or chunks support the 
generated answer.

A grounded RAG system should avoid inventing information that is 
not supported by retrieved evidence.


ADVANCED RAG

Naive RAG performs retrieval followed directly by generation.

Naive RAG can fail when the user query is ambiguous or poorly 
matched to the stored documents.

Query rewriting can improve retrieval by transforming a vague 
query into a more precise search query.

Query expansion can generate multiple related queries.

Multi-query retrieval searches for multiple interpretations of 
the same question.

Hybrid retrieval combines semantic vector search with keyword 
search.

Keyword retrieval is useful when exact terms, identifiers, 
product names, or technical expressions matter.

Dense retrieval represents queries and documents using 
embeddings.

Sparse retrieval represents documents using sparse lexical 
representations.

Reranking can reorder retrieved documents after an initial 
retrieval stage.

Corrective RAG evaluates retrieved evidence and can perform 
another retrieval step when the evidence is insufficient.

Self-RAG allows a model to reason about whether retrieval is 
needed and whether retrieved information supports its response.

Agentic RAG adds planning and tool use to the retrieval process.

A retrieval agent can decide which source to search, which query 
to use, and whether additional evidence is required.

A robust RAG system should have a maximum number of retrieval 
iterations.

Fallback behavior should be defined when no useful evidence is 
found.


VECTOR DATABASES

A vector database stores numerical representations of data and 
supports similarity search.

A vector is an ordered collection of numerical values.

Vector similarity can be calculated using cosine similarity, dot 
product, or Euclidean distance.

Cosine similarity measures the angle between two vectors.

A higher cosine similarity usually indicates greater semantic 
similarity.

Approximate nearest-neighbor indexes can make vector search 
faster for large datasets.

FAISS is a library for efficient similarity search over dense 
vectors.

Chroma is a vector database designed for storing and querying 
embeddings.

A vector database usually stores an identifier, embedding, 
document content, and metadata.

Metadata filtering can restrict retrieval to documents matching 
specific attributes.

For example, a RAG system can retrieve only documents where 
department equals engineering.

Vector dimensions depend on the embedding model.

Changing the embedding model can require rebuilding the vector 
index.


AI AGENTS AND TOOL USE

An agent can use a language model as a reasoning component.

A simple agent loop can be represented as:

User request -> Planning -> Tool call -> Observation -> Decision 
-> Final response.

The agent decides which action should happen next.

A tool schema describes the tool name, arguments, and expected 
behavior.

The language model generates a structured tool call.

The application executes the tool outside the language model.

The tool result is returned to the model as an observation.

The model can then decide whether another tool call is required.

Tool use allows a language model to interact with real systems.

Examples include SQL databases, search engines, calendars, file 
systems, calculators, APIs, and business applications.

Agents should validate tool arguments before execution.

Dangerous operations should require additional authorization.

An agent should not automatically receive unrestricted access to 
a system.

Tool failures should be handled explicitly.

Timeouts prevent a slow external service from blocking the 
entire agent.

Retries can recover from temporary failures but should have 
limits.

Idempotency is important when tools perform operations that 
change external state.

An idempotent operation can be safely repeated without producing 
unintended duplicate effects.


MCP

Model Context Protocol is a protocol for connecting AI 
applications with external tools and resources.

An MCP client communicates with MCP servers.

An MCP server can expose tools that perform operations.

An MCP server can also expose resources containing information.

The client discovers the capabilities provided by the server.

A model can decide to call an available tool through the 
application.

MCP provides a standardized interface instead of requiring every 
AI application to implement a completely different integration.

A database MCP server could expose tools for querying data.

A file-system MCP server could expose controlled file 
operations.

An application can connect to multiple MCP servers.

Security and authorization remain important when MCP tools can 
access private systems.

MCP does not make an AI model intelligent by itself. It provides 
a standardized mechanism for connecting models and applications 
to external capabilities.


AI SYSTEM SECURITY

AI applications should treat external text as untrusted input.

Prompt injection occurs when malicious or unintended 
instructions are included in user input or retrieved content.

A retrieved document should not automatically be treated as an 
instruction to execute actions.

Tool permissions should be restricted.

Sensitive operations should require authorization.

Secrets such as API keys and passwords should not be placed 
directly into prompts or source code.

Environment variables can be used to provide configuration 
values securely.

Logs should avoid exposing sensitive information.

Input validation should happen before external tools are called.

Output validation can detect malformed or unsafe results.

Production systems should define clear trust boundaries between 
users, models, retrieved content, and tools.


AI EVALUATION

Evaluation is necessary to determine whether an AI system 
actually works.

A language model can be evaluated using held-out text and 
next-token loss.

A RAG system should evaluate retrieval separately from 
generation.

Retrieval recall measures whether the correct information 
appears among retrieved results.

Precision measures how much of the retrieved information is 
relevant.

Generation evaluation can measure correctness, relevance, 
groundedness, and clarity.

A benchmark dataset should contain representative questions and 
expected answers or supporting documents.

Regression tests ensure that changes do not unexpectedly reduce 
system quality.

A model should be tested on both normal and difficult inputs.

Evaluation prompts should cover the intended use cases of the 
application.

Human evaluation can identify problems that automated metrics 
miss.


DEPLOYMENT

Model inference means running a trained model to generate 
predictions.

A model can run locally on a CPU or GPU.

Quantization reduces the numerical precision of model parameters 
to decrease memory usage.

Common numerical formats include FP32, FP16, BF16, INT8, and 
lower-bit representations.

Smaller numerical formats can reduce memory requirements but may 
affect model quality.

CPU inference can be useful for small models and development 
environments.

GPU inference is usually much faster for larger neural networks.

Batch inference processes multiple inputs together.

Streaming generation returns generated tokens incrementally 
instead of waiting for the complete response.

A model server exposes inference through an application 
interface.

Monitoring should track latency, throughput, errors, memory 
usage, and model quality.

A production deployment should have a rollback strategy for 
problematic model versions.
